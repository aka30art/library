# LIBRARY — Phase 02 Semantic Audit of Prompt Bodies, Templates & Synthesis

Date: 2026-11-21
Baseline: production main at 4523d5239ea6feb34bcff47923e3bd6fff63161e
Scope: actual catalogue prompt factory, prompt-mode wrappers, contextual option system, Prompt Intelligence, Randomiser synthesis, all collection-level generation behaviours.
Status: completed audit and correction decisions; catalogue is intentionally not modified in this phase.

## Audit method and scope boundary

The catalogue expansion records are largely generated from a shared factory: the individual title/element is substituted into a category-specific instruction, then given a universal application instruction, negative constraints, metadata and model compatibility. This means semantic audit must evaluate both the shared template that determines prompt behaviour and the variable title that determines the individual output. The audit inspected the actual prompt-generation factory, all five prompt modes/wrappers, contextual option logic, Prompt Intelligence, Randomiser selection and synthesis logic, and collection inventories previously reviewed in Phase 01.

The prompt bodies are not 1,521 independent handcrafted paragraphs. They are generated by shared category templates. Consequently, the most meaningful audit unit is the 15 template families plus title-variable differentiation, not a claim that every expanded body has unique prose. Title-level KEEP/REFINE/MOVE/MERGE/RETIRE/CONVERT decisions below are based on inventory overlap and existing template behaviour. A final targeted review of flagged title clusters is required before destructive catalogue operations. This audit does not claim a blind full proofread of every literal title with an individual custom paragraph.

## Overall verdict

KEEP the 15-collection architecture; REFINE the shared prompt-generation logic and metadata. The catalogue is not fundamentally broken. Its principal weakness is that good concepts are sometimes given generic or conflicting execution wrappers, and the catalogue's taxonomy and synthesis layers cannot consistently express the distinction between a style, a method, a material, a surface, a scene/world and a photographic edit.

No blanket catalogue rewrite is justified. The safest and most valuable correction is a template and data-contract upgrade followed by focused record batches.

# 1. Shared prompt modes — decisions

## 1.1 Direct prompt — KEEP / REFINE

KEEP: Each prompt's native category instruction and universal application/exclusion context as the direct/default prompt. This is the most efficient prompt mode for image models and generally the least padded.

REFINE: Current instruction construction is largely one universal application paragraph with the same negative prompt list applied across categories. Improve each template's ability to state target scope, allowed change, subject-preservation rules and failure modes without adding filler. Use category-specific negative constraints rather than one-size-fits-all exclusions.

Issue: The shared negative list is over-general for some categories. "Unrelated scenery" is helpful for subject transformations, but a world-building, architecture or composition prompt may require deliberate scene additions. The instruction should be conditional on category/brief, not absolute.

Decision: KEEP the short direct mode, REFINE negative constraints and scope rules.

## 1.2 Universal ART DNA master prompt — KEEP / REFINE

KEEP: The master prompt has a coherent art-direction, craft/fidelity, preservation and output-intent structure. It improves decision-making instead of merely restating the prompt.

REFINE:
- Its direction to refine camera perspective, negative space, depth, atmosphere and lighting is not universally appropriate (e.g., strict flat-vector graphics, graphic design, source-locked photographic edit). Make those directions conditional and relevant.
- "Physically or stylistically coherent behaviour" is useful, but the master should respect the target type. A flat illustration should not be pushed into realistic surface response; a camera-locked post-edit should not be given new perspective.
- Preservation rules need a clear precedence rule: explicit transformation permissions override generic source-preservation only in the area they authorize.
- Avoid the master adding effects or scene complexity by default.

Decision: KEEP as the premium art-direction wrapper; REFINE with scope-aware rules and hierarchy of constraints.

## 1.3 Universal variable template — REFINE (highest template priority)

The variable-based prompt contains many bracketed fields, then a second prose generation brief that repeats the same fields, then the source category prompt, then another quality-control paragraph. It is useful as a reusable prompt skeleton, but its current shape can become repetitive and may invite the image model to interpret unresolved variables.

Issues:
- A large field list is not necessarily helpful for simple style/material/effect transforms.
- A second GENERATION BRIEF repeats the fields rather than adding decisions.
- The prompt tells the user to remove irrelevant fields but provides no automatic resolution; unfilled placeholders can survive if copied incompletely.
- Subject-specific direction is appended after the generic brief and may conflict with variables (e.g., target material vs. visual style; preservation vs. environment; palette vs. named film grade).
- It has no explicit precedence/constraint reconciliation instruction.
- The negative prompt is appended last as a literal field, but user-facing modes need a clear distinction between negative prompt text and natural-language constraints for models that do not support a separate negative field.

Decision: REFINE. Replace the large duplicate form with a compact modular prompt compiler:
1. Brief and subject anchor.
2. Target treatment and scope.
3. Only applicable parameters.
4. Domain-specific execution.
5. Fidelity/constraint precedence.
6. Quality check and output requirement.
Remove redundant prose and require final placeholder resolution.

## 1.4 Screen-world transformation — KEEP / REFINE

This is materially stronger than the generic transform wrapper: it explicitly treats the source as identity anchor, allows costume/scene changes, rebuilds world/environment, applies production language and preserves source recognizability.

Issues:
- It repeats preservation/recognizability requirements across several sections.
- It relies on named universe-specific prompt direction but can overfit to broad genre tropes when the actual source title is distinctive.
- It could generate logos, written marks or existing named characters incorrectly if the title-level direction is not sufficiently constrained; the current no-logos/no-watermarks/no-substitution constraints are useful.
- A universal optional scene field is a good idea, but should be contextual and not required when a prompt's scene is the main intent.
- Source subjects of different types (human, animal, object) are handled, but source-preservation language can be shorter and more precise.

Decision: KEEP; REFINE into one tighter, hierarchy-aware screen-world transformation. No franchise prompt should be retired solely because the wrapper is repetitive.

## 1.5 Generic transformation wrapper — REFINE (high priority)

The wrapper says to apply a treatment and preserve the source subject's identity, defining features, shape, proportions, pose, expression, objects and composition, modifying only visual treatment. This is reasonable for image edits, but too restrictive for some categories.

Conflicts:
- Materials: subject may need surface, construction, reflectance, translucency or shape adaptation for a convincing material embodiment.
- Styles: some styles change linework, geometry, proportions, spatial grammar or composition, so locking all of these can weaken transformation.
- Textures: source silhouette should remain, but the visible surface and microstructure should change.
- Effects: effects that require motion, temporal trails, distortion or spatial warping are constrained by unchanged composition/geometry.
- Composition: recomposition is the main objective, but the wrapper says composition must remain unchanged. This is a direct instruction conflict.
- Rendering: method may legitimately change lighting, shading, volumetrics and surface presentation.
- Photography Post-Edits: fixed-source preservation is appropriate, but transformations such as double exposure, tilt-shift, long-exposure composites, selective retouching or infrared may require local or controlled content modification.

Decision: REFINE into category-aware source permissions. Do not require every category to preserve the entire composition. Define immutable source facts, permitted changes, and optional changes per category. Composition prompts explicitly allow reframing/rearrangement; post-edit prompts remain capture-locked except for the selected edit.

# 2. Collection template decisions

## Materials — KEEP / REFINE

Current category direction is strong: the subject should embody the material, material behaviour should be dominant, subject identity should remain readable and the treatment should unify the form. The materials list has breadth across metals, minerals, glass/ceramics, natural substances, textiles, engineered materials, smart/optical materials and experimental composites.

REFINE: Define material physically, not only visually. Require appropriate scale, thickness, structural behaviour, surface finish, translucency/opacity, reflectance, weight cues, seams/joins and deformation where applicable. Some catalogue items are material families or composites rather than singular materials; add a type facet. Avoid assigning implausible material properties indiscriminately.

KEEP: materials as a core category; no mass retirement.

## Styles — KEEP / REFINE

The category template is coherent: use one aesthetic as a unified visual language while preserving subject identity. Inventory breadth is valuable across art movements, design disciplines, illustration traditions, subcultures, digital aesthetics and hybrid movements.

REFINE: Some entries are movements, some medium/technique, some design systems, and some internet subcultures. Add style-type facets and stronger definitions so a title controls shape language, mark-making, composition, colour, typography, detail and cultural context as appropriate. Do not treat a style as a colour filter.

MOVE candidates: pure design-production techniques (e.g., risograph aesthetics, woodcut printmaking, generative plotter art) should be considered for a technique/production facet or Graphic Design & Layout only if the outcome is better served there. Cross-collection placement should not remove them from Styles if style transformation is the actual use case.

## Textures — KEEP / REFINE

The template has appropriate surface-focused intent and source preservation. The inventory ranges from macro topology to microstructure, biological surfaces, textile structures, food textures and print/recording artefacts.

REFINE: Add scale, directional logic, density, coverage, relief/depth, interaction with underlying material and focal priority. Distinguish a surface texture from a material identity, a process artefact and a pattern. Do not force texture over areas where it damages readability.

MERGE candidates: cracked/crazed/craquelure ceramic glaze variants; orange peel surface vs orange-peel powder-coat dimples (must distinguish natural peel from coating microtexture); hook-and-loop field vs microhooks; several grain/noise/abrasion microdetail entries. Only merge after body/visual-outcome verification.

## Photography Post-Edits — KEEP / REFINE / RENAME

The category's capture-lock premise is a strong and necessary safeguard. The actual inventory is broader than post-edit/grade: film emulation, historical photographic processes, retouching, print simulation, composites, degradation, archival restoration and environmental colour grades.

REFINE: Explicitly split edit families and use a source-lock profile. Separate grade-only edits from compositing/retouching and image reconstruction. Preserve source geometry/identity and do not introduce new camera capture; permit only named changes.

RENAME: Recommended display name Photography & Image Treatments (preferred) or Photography Finishing. The former is clearest because the catalogue includes more than finishing. Before changing the legacy key lighting, test all category ID dependencies, filter labels, options, randomiser mapping, taxonomy, count badges and saved/bookmarked data compatibility.

KEEP: current prompt records pending focused overlap review.

## Effects — KEEP / REFINE

The category is effect-first, but the template doesn't differentiate effect mechanism, source, spatial coverage, intensity, temporal behavior, depth and subject interaction. Current universal wording could lead to pasted overlays or uncontrolled effects.

REFINE: Each effect should specify what generates it (optics, light, surface, atmosphere, temporal sampling, image signal, geometry, etc.), where it occurs, how it behaves, its intensity, its relationship to the subject and whether it is additive or transformative. Add effect mechanism facets.

MERGE candidates: chromatic aberration vs RGB channel separation; halation vs glow/spherical-aberration-like bloom; photocopy degradation vs photocopy-generation collapse; databending vs datamoshing; thermal imaging vs thermal contour overlay; refraction vs spectral dispersion. Keep only distinct outcome/controls.

## Composition — KEEP / REFINE (critical conflict)

The catalogue's composition template explicitly permits recomposition. The generic transformation wrapper later prohibits composition changes. This makes the prompt mode contradictory.

REFINE: Composition must override generic preservation for framing, position, scale, arrangement, viewpoint and spatial relationships. Preserve subject identity and required elements only. Define composition technique, intended hierarchy, focal path, balance, framing, negative space, viewpoint and output layout.

MERGE candidates: Golden ratio/Fibonacci/golden spiral variants; bilateral/central symmetry; radial arrangement/radial symmetry; diptych/triptych variants; perspective types; orthographic/isometric/axonometric arrangements. Retain specialized forms only when the output is measurably different.

## Rendering — KEEP / REFINE

Rendering category correctly intends the method to govern image creation, but its current generic wrapper does not explain the operational difference between rendering techniques. Titles range from rendering algorithms to shading, reconstruction, geometry, volumes, technical visualisation and non-photorealistic methods.

REFINE: Each rendering prompt must identify pipeline/technique, relevant physical or stylized assumptions, primary visual signature, controls, limitations and suitable subject. Rendering method should not be conflated with style or final image aesthetic.

MOVE candidates: pure aesthetic NPR/style entries to Styles; technical product/CAD visualisation modules to Product Design or specialist visualisation facets. Keep distinct technical methods in Rendering.

## Colour & Atmosphere — KEEP / REFINE

The category prompt gives a coherent unified colour/atmospheric direction. It needs to separate palette logic from atmospheric depth.

REFINE: Palette modules should define colour relationships, dominant/support/accent roles, temperature, saturation, contrast and tonal distribution. Atmosphere modules should define spatial depth, light scattering, particulate density, environmental interaction and subject separation. Colour grade and atmosphere are compatible but not the same facet.

MERGE candidates: monochromatic/near-black chromatic variants; overlapping muted-earth/mineral-pigment palettes; pastel colour scheme vs pastel haze; fog/mist/haze variants when the visual result is too similar.

## Films & Shows — KEEP / REFINE

The screen-world wrapper is one of the strongest templates because it transforms subject design and environment, not only surface colour. It needs a stronger title-specific visual identity and controlled permissions.

REFINE: distinguish franchise/source-world, character/creature, production design, visual style and setting/era. Use brand/franchise parents with contextual options for variations where practical. Ensure the source identity is not confused with the target franchise character. Avoid generic genre substitutions.

MERGE / CONVERT candidates: duplicate universe/era entries into options where they share a parent world and output type. Do not merge medium-specific adaptations (e.g. anime vs live-action vs film) when the visual grammar differs. Keep one-off titles with genuinely unique prompt directions.

## Toys & Collectibles — KEEP / REFINE / CONVERT

Collectible prompts should generate a product/collectible object, not merely make the subject toy-like. The Randomiser's collectible bucket has object construction language but some entry bodies remain generic transformations.

REFINE: Add collectible format, scale, pose/stand, moulded-part logic, articulation, paint/decal, packaging, material, display, camera and collector intent as relevant. Separate toy/figure conversion from card art, packaging, accessories and product photography.

CONVERT_TO_OPTION: TCG brand-specific type, rarity, finish, foil, border/frame, serialisation, alternate art and special treatment should become parent-prompt configuration. Preserve unique rarity treatment as option data, not standalone prompt entries. Keep card-back, booster pack, slab, playmat, packaging, non-TCG toys and other unique collectible product prompts.

## Architecture & Spaces — KEEP / REFINE

Specialist architecture template/bucket is conceptually appropriate. Titles are not enough to guarantee a complete architectural brief.

REFINE: require site/climate/context, programme, users, access/circulation, massing, structure, material system, daylight, environmental performance, spatial sequence and drawing/render type as applicable. For interior-only prompts, avoid irrelevant site/massing variables. Preserve context-specific constraints.

## Sculpture & 3D Objects — KEEP / REFINE

REFINE: sculpture should be defined by intent, form grammar, mass/void, balance, gravity, material, fabrication/assembly, scale, site, interaction and presentation. Distinguish sculpture from decorative object, product and architecture.

MERGE candidates: compressed volume/precision stack; interlocking modules/cut-and-stack; kinetic and counterbalanced/suspended variants; organic growth/cellular variants. Merge only if the generated form and construction are indistinguishable.

## Graphic Design & Layout — KEEP / REFINE

REFINE: Use a complete communication brief: format, audience, message, hierarchy, grid, typography, image/text relationship, colour, production process and output. Ensure meaningful, readable text where requested; do not generate placeholder pseudo-copy. Design-only modules should not be forced into 3D scenes.

MOVE candidates: pure illustration and fine-art styles to Styles when style transformation is the primary outcome; print techniques may remain cross-faceted in Graphic Design & Layout and Styles.

## Photography & Camera — KEEP / REFINE

REFINE: Prompt must control photographic intent and actual camera choices: subject, viewpoint, lens behaviour, camera-to-subject distance, exposure, aperture/shutter/ISO where relevant, lighting, focus plane, depth, motion and framing. Camera-motion prompts must distinguish camera motion from subject motion and resulting blur.

MERGE candidates: panning/tracking/dolly/orbit/zoom-burst/camera-shake variants only if camera movement, subject movement, and exposure effects are not differentiated. Keep distinct lens character, capture technique and genre.

## Product Design — KEEP / REFINE

The Randomiser product bucket contains appropriate design constraints (use-case, affordance, ergonomics, manufacturing, assembly, tolerance, safety, serviceability), but individual generic transformation bodies may not reliably express them.

REFINE: Product-design prompts must define user, problem, task, context, requirements, functional architecture, affordances, ergonomics, manufacturing, tolerances, assembly, safety, durability, serviceability, lifecycle and output view. Do not let speculative aesthetics replace functionality. Provide realistic constraints for consumer/industrial/assistive use.

# 3. Prompt Intelligence — decision: REFINE (not replace)

The module has useful category roles, term lists, category compatibility maps, pairwise scores and conflict patterns. It is an intelligent baseline, not yet a semantic engine.

Verified limitations:
- It derives many labels by substring matching. Keyword presence is not proof of the concept, nor does missing a term prove absence.
- Title and prompt can repeat the same term, so detection can overcount signals.
- Terms are incomplete, and the same keyword may have different meaning by category.
- Conflict patterns are explicit and useful but sparse. They cover a small number of common oppositions, not the full domain.
- Compatibility is largely category-level plus shared tags/term overlap, rather than actual selected instructions and subject-specific feasibility.
- It can penalize same-category combinations even when two different modules are intentionally complementary, and cannot reliably distinguish redundant same-category pairings.
- Category compatibility is coarse. A combination can be category-compatible but conceptually incompatible at the title or subject level.
- Score/warnings should be presented as heuristic guidance, not a reliable semantic verdict.

KEEP: category role map, category compatibility map, pairwise analysis and warning UI.

REFINE: add explicit prompt metadata (role, operation, scope, intensity, subject compatibility, tags, conflict/compatibility declarations); normalize term detection; build broader conflict rules; evaluate selected option instructions; make warnings explain the specific pair and suggest a resolution. Don't discard the module or make it a gate that blocks creative experimentation.

# 4. Randomiser — decision: KEEP / REFINE / RETEST

The current Randomiser has strong architectural intent: category buckets, smart vs experimental modes, repeated sampling (72 attempts), compatibility scoring, conflict penalties, and an integrated prompt with role-specific constraints.

Verified issues:
1. Randomiser uses a category list that includes separate Films & Shows subcategories. Its matching relies on category plus a tags check. This is fragile if labels/subcategory tags change.
2. Smart sampling runs a fixed 72 candidate trials. This is not a guarantee of optimality and may not be enough or may be wasteful depending on selected counts.
3. Smart scoring averages pairwise compatibility, adds category diversity and penalizes unique warning count. A single warning can be disproportionately penalized, and diversity can reward adding a category without checking its actual contribution to the creative thesis.
4. Conflict analysis is heuristic. Experimental mode should allow deliberate collisions, but should not produce a contradictory prompt that is impossible to execute unless the mode explicitly asks for an impossible/abstract hybrid.
5. Prompt compaction extracts preferred labeled blocks from prompts, but most current generated catalogue prompt bodies do not use these labels. As a result, compactDirective can retain a whole raw prompt and then truncates it at 1,050 characters. The selected directive may be cut mid-thought, or may be too long/noisy. This is a structural risk, not evidence that every output is broken.
6. Synthesis includes category buckets and role-specific instructions, which is a strength, but prompt selection is not subject-aware and does not have reliable metadata to avoid stacking redundant operations.
7. The generated master prompt is a single integration wrapper. It can become verbose and repeat the same constraint across multiple sections; the final text should be dynamically structured based on chosen modules rather than fixed prose.

KEEP: two modes, random selection, coherence assessment, domain buckets, one unified prompt output.

REFINE: prompt compiler; metadata-driven sampling; weighted compatibility; contribution-aware role diversity; subject-aware constraints; contradiction resolver; smart mode with explainable rationale; experimental mode with explicit collision framing; remove fixed-trial assumptions where a more efficient deterministic candidate strategy is possible.

RETEST: single selection, same category multiple modules, maximum quantities, screen-world with styles, material with texture, photography finish with effect, architecture with product/sculpture, incompatible color/style, experimental mode, prompt output length and copy/export.

# 5. Contextual Options — decision: KEEP / REFINE / CONVERT

The option system has useful examples with real instructions (e.g. slab grade/case/label, booster pack format/wrapper/retail display, playmat surface/layout/edge, card back architecture/pattern/finish, and TCG parent card type/rarity/finish). These are meaningful configurators, not merely dropdown decoration.

Issues:
- Option coverage is uneven across the collections.
- Options are conditional on title/category rules, which are brittle if titles or subcategory names change.
- The option instructions are appended to the base prompt. This works, but selected options need a precedence and conflict check with the base prompt and other options.
- Some option families (rarity/foil/card type) have overlapping or mismatched values across TCG brands; brand-specific values should be curated.
- Generic options should be sparse. Adding controls where they have no real creative consequence increases friction.

KEEP: current meaningful configurators.

REFINE: option schema and integration rules; metadata-based targeting rather than title regexes; ensure option values are prompt instructions; conflict-aware option compilation.

CONVERT_TO_OPTION: TCG variations, screen-world era/medium/production variations, collectible packaging/finish variations, and other variants that are the same core parent task with selectable parameters. Only convert when parent task remains stable.

# 6. Cross-collection decisions queue

These are targeted decisions for later implementation; no entries are changed in this audit.

## KEEP
- The 15-collection architecture and domain-specialist collections.
- Core Materials, Styles, Textures, Effects, Composition, Rendering, Colour & Atmosphere, Films & Shows, Toys & Collectibles, Photography & Camera, Product Design.
- Domain-specific concepts that are distinct in operation and output.
- Existing direct prompt mode and premium ART DNA wrapper.
- Screen-world complete transformation logic.
- Useful compatibility/conflict analysis and contextual options.

## REFINE
- All 15 shared template families for scope-aware constraints and domain-specific output contracts.
- Universal master prompt to make creative direction conditional on category.
- Variable template to reduce repetition and compile only relevant fields.
- Generic transform wrapper to resolve the composition/preservation conflict and category permissions.
- Negative prompt scope, with conditional exclusions.
- Prompt Intelligence term/compatibility/conflict data and heuristics.
- Randomiser prompt compilation, compact extraction, scoring, subject awareness and validation.
- Contextual option targeting and conflict/precedence rules.
- Primary subcategory metadata and cross-facets.
- Collection descriptions and browse facets where taxonomy is inconsistent.

## MOVE (candidate; review before final move)
- Rendering-only methods to rendering facets.
- Pure art styles currently mixed with rendering or production technique to Styles or a cross-facet.
- Design-production techniques from Styles to Graphic Design & Layout where deliverable-based browsing is more useful.
- Screen-world style/format entries to an explicit style/format record type or facet.
- Materials records that are composites, surface finishes, processes or product forms to type facets, not necessarily to a different collection.
- Photography post-edit records that are compositing/retouching/degradation rather than grade-only to dedicated image-treatment facets.
- No move should be made solely to satisfy a regex.

## MERGE (candidates; only after prompt outcome comparison)
- Near-identical material identities/finish forms and overlapping material families.
- Texture pairs with similar surface results (crackle/crazing; orange-peel surface vs coating; hook-and-loop variants; micro-scratch/noise/abrasion).
- Effects pairs (aberration/channel separation; glow/halation; photocopy degradation; data corruption; thermal imagery).
- Composition families (golden ratio/spiral; symmetry; diptych/triptych; perspective and projection variants).
- Rendering technique overlaps (GI/path tracing variants; volume rendering; neural reconstruction; SDF/geometry; subdivision/microdisplacement; toon/cel/NPR variants).
- Colour/atmosphere families (similar palettes and fog/mist/haze variants).
- Screen-world franchise duplicates where the same parent and operation are repeated; preserve adaptation differences.
- Specialist titles whose design intent, construction and output are substantially identical.

## RETIRE (candidates; not yet approved for deletion)
- Redundant rarity-specific TCG prompt records after their unique treatment is preserved as parent configurator values.
- Duplicate screen-world records where parent and variant are genuinely the same task.
- Generic/weak titles that do not produce a distinct outcome after prompt compilation.
- No entry is retired simply because its title is similar. Use its prompt outcome as the deletion/merge test.

## CONVERT_TO_OPTION
- TCG rarity, card type, finish, foil, border/frame, serialisation, alternate art, special treatments.
- Franchise/world variants sharing a parent universe and transformation objective (era, adaptation medium, location, character class, scene role).
- Collectible form factor/packaging/finish variants when they are the same underlying product task.
- Similar composition/rendering/effect intensity or parameter variations only if those choices change an otherwise stable task.

## ADD_MISSING
- Materials: physical behaviour, finish, scale, structural form, process and material-type facets; more robust rare/experimental material coverage only where a gap is confirmed.
- Styles: style type (movement, medium/technique, design discipline, subculture, hybrid) and clearer output contracts.
- Textures: scale, coverage, directional behaviour, substrate compatibility, micro/macro facets; fill genuine gaps only.
- Photography & Image Treatments: facets for film emulation, colour grade, retouching, print/chemical, composite, degradation, restoration; source-lock profile.
- Effects: mechanism, source, intensity, coverage, depth, temporal behavior and subject interaction.
- Composition: operation/geometry, framing, viewpoint, perspective, arrangement, visual hierarchy, aspect/layout.
- Rendering: pipeline, algorithm, geometry, shading, volume, simulation, reconstruction, technical visualization, NPR.
- Colour & Atmosphere: palette roles, harmony, tonal grade, temperature, atmosphere, depth and phenomena.
- Films & Shows: source type, franchise, medium/adaptation, era, setting, production style, variant parent.
- Toys & Collectibles: product type, scale, construction, articulation, packaging, display, card type and finish.
- Architecture: site/context, climate, programme, circulation, accessibility, structure, daylight, environmental performance and output type.
- Sculpture: form, mass/void, gravity, assembly/fabrication, scale, site, motion, interaction.
- Graphic Design: audience, message, format, hierarchy, grid, typography, image/text, print/screen and production.
- Photography: lens/camera, viewpoint, exposure, focus, movement, subject/genre and capture intent.
- Product Design: user/task, requirements, architecture, ergonomics, material/process, manufacturing, tolerances, assembly, safety, durability, serviceability, lifecycle and presentation.
- All collections: explicit subject compatibility, scope, operation, intensity, preservation permissions, negative constraints and prompt role metadata.

## Final correction order (recommended)

### Batch 1 — Prompt compilation and constraint hierarchy
Fix the generic transform conflict; tighten Master ART DNA; replace variable template repetition with a compact conditional compiler; make negative constraints category-aware. This is the most leverageful improvement because it affects the entire catalogue.

### Batch 2 — Metadata and taxonomy contract
Introduce stable primary subcategory, secondary facets, record type, creative operation, scope, subject compatibility and option-target metadata. Keep regex as a legacy fallback only. Add coverage validation.

### Batch 3 — Collection-native template upgrades
Refine Materials, Styles, Textures, Effects, Photography & Image Treatments, Composition, Rendering and Colour & Atmosphere; then specialist collections and Films & Shows/Toys. Each batch gets test prompts and output comparisons.

### Batch 4 — Option schema and prompt intelligence
Replace brittle title-based option routing; integrate selected instructions, compatibility and conflicts; curate the TCG parent options.

### Batch 5 — Randomiser 2.0 synthesis
Replace raw-text truncation with semantic module compilation. Ensure the output is one integrated creative proposition and preserves the unique contribution of each selected module.

### Batch 6 — Catalogue corrections
Execute verified KEEP/REFINE/MOVE/MERGE/RETIRE/CONVERT/ADD decisions in reviewed batches. Publish inventory delta and rationale.

### Batch 7 — Validation
Tests for every template and collection, record integrity, primary subcategory coverage, options, compatibility/conflicts, randomiser outputs, copy/export, browser smoke tests, mobile/desktop, and production deploy only after merge.

## Decision policy

- KEEP means preserve the concept and its current catalogue presence; it does not mean the shared template is exempt from improvement.
- REFINE means rewrite or strengthen execution without changing the concept.
- MOVE requires a demonstrably better primary collection and preserves cross-facets where possible.
- MERGE requires substantially equivalent creative output, not title similarity.
- RETIRE requires a unique-function check and lossless migration of useful instruction content.
- CONVERT_TO_OPTION requires a stable parent task with genuinely parameterized variants.
- ADD_MISSING requires a confirmed capability gap, not a preference for more volume.

**Phase 02 verdict:** No production catalogue records are changed. The next phase should implement Batch 1 only, in an isolated PR, with representative prompt before/after comparisons and test coverage. Do not begin large catalogue deletion/migration until the compiler and metadata contract are ready.
